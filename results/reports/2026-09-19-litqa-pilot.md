# Исходный baseline перед подбором локальных моделей

**Подготовка этапа 3 завершена для первого рабочего пилота.** Есть воспроизводимый
запуск, фиксированные данные, первая полная таблица и разбор ошибок. Текущая
конфигурация имеет заметные ограничения; она задаёт исходную точку для этапа 4.
Это не результат сравнения моделей и не доказательство улучшения PaperQA.

Run: `20260919T155917Z-d979c5`, выполнен 19 сентября 2026.
[Числа и provenance](2026-09-19-litqa-pilot.json),
[разбор источников](2026-09-19-litqa-pilot-review.json),
[правила оценки](../../docs/evaluation-protocol-v1.md).

## Что подготовлено

- PaperQA закреплён на `57e89f7223b0960d5ee5ea048c69e3c47e088572`, зависимости
  закреплены в `uv.lock`. Библиотека не изменена.
- Начальные модели: Qwen3 8B Q4_K_M для controller, RCS и ответа;
  nomic-embed-text F16 для embeddings. Digest обеих моделей сохранён.
- Корпус: 16 открытых статей, извлечённых из Europe PMC JATS в UTF-8 TXT.
  Вопросы: 8 рабочих и 8 резервных из закреплённого LitQA2. Резерв не запускался.
  Все исходные и извлечённые тексты проверены по хешам; реальный upstream
  TXT-reader читает все 16 документов без расхождений с UTF-8-источниками.
- Ограничения исходной конфигурации: контекст 8192, output cap 768, thinking off,
  evidence_k=3, answer_max_sources=3, 8 шагов агента, agent timeout 900 секунд,
  outer timeout 1200 секунд. Это явные отличия от настроек upstream по умолчанию.
- Автоматическая оценка букв, раздельные статусы, raw evidence/RCS, журналы
  инструментов, тайминги, доступные счётчики токенов и условия запуска сохраняются.
  По центральным ответам всех восьми вопросов выполнен assistant review;
  отдельные дополнительные утверждения разобраны, исчерпывающего claim scoring нет.

## Что означают ошибки

**RfaH и αPrePro-HsMOR:** ответ есть в корпусе, но использованные фрагменты/резюме
не дали требуемого доказательства. Отказы засчитаны как пропуски на отвечаемых
вопросах. В ответе про HsMOR также есть неподтверждённый перенос свойства между
разными условиями эксперимента — отказ сам по себе не гарантирует чистое объяснение.

**COSA-1:** нужный raw-фрагмент уже найден. В нём удаления до 30-й аминокислоты
сохраняют взаимодействия, а удаление до 40-й их ослабляет. RCS пропустил это
решающее сравнение и пересказал только результаты для первых 53 аминокислот.
Финальный ответ ошибочно выбрал участок 1–10 вместо 31–40. Это конкретный
случай потери важной детали при суммаризации и неверного вывода после неё.

**Хромосома:** два поиска и два сброса evidence исчерпали лимит восьми шагов.
Встроенный fallback нашёл правильный фрагмент и ответил верно, но статус
остался `truncated`. В дополнительном объяснении также появился неподтверждённый
вывод о физической длине из числа syntenic gene pairs.

**TMPRSS2:** правильный ответ 80 уже был сформирован. Затем controller пять раз
вернул обычный текст `Final answer: C` вместо tool call; библиотека выставила
`fail`. Это ограничение наблюдаемой связки Qwen3/Ollama/ToolSelector. Его нельзя
скрывать только потому, что содержательная часть ответа верна.

Даже в правильном ответе про Wyeast 3068 есть дополнительный вывод о сниженной
способности к flocculation, который не установлен цитируемым абзацем об enrichment
удалённых генов. Эти примеры мотивируют проверку утверждений, но не доказывают
эффективность будущего verifier: он пока не реализован.

## Готовность к следующему шагу

**Сейчас от студента не требуется установка, доступ к серверу или API-ключ.**
Следующий совместный шаг — разобрать эту таблицу и выбрать первый объект
сравнения: например, надёжность управляющей модели либо полноту и точность RCS.
Конкретные модели ещё не выбраны. Затем меняем одну роль, повторяем тот же dev
набор и сравниваем качество, поддержку источниками и ресурсы по одному протоколу.

Перед итоговыми исследовательскими выводами желательно заранее расширить резерв;
восемь вопросов дают только предварительный сигнал. До фиксации конфигураций
holdout не используется для подбора. Наш малый OA/text-only корпус и настройки
не воспроизводят опубликованные показатели PaperQA2. H1–H3 proposal этим
baseline не проверены. Verifier, новая политика поиска и обучение не выполнены.

Проверки реализации: **29 pytest tests**, Ruff lint/format. Хеши кода inference
в момент завершения совпадают со snapshot текущего прогона. Для восстановления
запуска использовать README и protocol; сырые результаты находятся локально
в `results/runs/20260919T155917Z-d979c5/`.
