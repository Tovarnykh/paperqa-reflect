## Проверка источника и ограничения

Вопрос: какой ложный визуальный признак использовала нейросеть для распознавания
лошадей в примере из статьи? Правильный вариант — watermark фотографа.

В последнем прогоне использована цепочка:
`paper_search → gather_evidence → gen_answer → complete`.
Исходный фрагмент `pqac-7a07f01e`, страницы 2–4, содержит нужное утверждение;
оно также проверено по изображению страницы 2 исходного PDF. Это ручная проверка
центрального факта, не автоматическая верификация всех предложений ответа.

В более раннем прогоне одно резюме неверно описало два примера как примеры
распознавания лошадей; в статье второй пример относится к медицинским изображениям.
Оценка релевантности этого резюме была 10. Это конкретное наблюдение для будущего
разбора RCS/verifier, а не измеренная частота ошибок.

В `response.json` PaperQA очищает исходные тексты Context для выдачи пользователю.
Полные фрагменты сохранены **до этой очистки** в `evidence-progress.json` и
`session-progress.json`; оба использованных фрагмента последнего прогона имеют
по 3000 символов. Не надо восстанавливать исходное evidence из одного answer.md.

Набор содержит один документ и пять подготовленных вопросов, но фактически
проверен только smoke-01, с повторами при отладке. Остальные четыре вопроса,
корпус с отвлекающими статьями и отдельный evaluation-набор — дальнейшая работа.
В проекте ещё нет собственного verifier, нового алгоритма остановки или сравнения моделей.
