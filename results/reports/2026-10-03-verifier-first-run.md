# Первый локальный verifier реализован и запущен

**Позднее уточнение, результаты не менялись:** [evaluation v2](../../docs/evaluation-judge-protocol-v2.md) заменяет описанный ниже human-review gate внешней модельной оценкой. Ручная разметка Viktor не требуется; внешних judge-результатов пока нет.

3 октября 2026. По прямому поручению пользователя создан отдельный observer,
проверяющий готовые claims по оригинальным cited passages. Используется
установленный Qwen3.8 27B Q4_K_M через Ollama на университетской V100.
Модель не обучалась; агент PaperQA и выбранный baseline не изменены.

## Что реализовано

- `python -m paperqa_reflect.verifier plan/run`: отдельный CLI без импорта runner
  PaperQA; вход только claim и указанные полные исходные фрагменты.
- JSON schema для supported/contradicted/insufficient, точная проверка source IDs
  и дословного присутствия evidence; offsets рассчитываются программно.
- Технические проблемы выделены в not_checked. Каждый запуск сохраняет запросы,
  raw responses, ошибки, время, token counts, model digest, prompt/config/schema
  и SHA-256 кода; snapshot исполненного кода сохранён вместе с результатами.
- Отдельный `verifier_report`: сравнение с labels после inference, раздельные
  natural/controlled таблицы, confusion matrix и учёт непроверенных случаев.

[Руководство и команды](../../docs/local-verifier.md),
[протокол](../../docs/claim-verifier-protocol-v1.md).

исправлением ответов не пройден.

## Единственное расхождение: cv-024

Это искусственная подмена похожего названия категории. Источник перечисляет
несколько обогащённых функций, включая asparagine catabolism. Claim вместо этого
говорит arginine catabolism. Черновая метка — insufficient: отсутствие категории
в перечислении само по себе не доказывает её отсутствие в исследовании.
Verifier пометил contradicted; его пояснение само опирается на неупоминание и
формулировку «likely contradicted». Неверное различение недостаточной поддержки и
прямого противоречия — кандидат для ручной проверки, а не основание молча заменить
label или повторить только этот пример до нужного ответа. Prompt после результата
не менялся, новых повторов не было. Источники/вердикты сохранены.

## Проверки и происхождение

Ruff и **76 тестов** проходят локально и на сервере. Новые проверки охватывают
совместные источники, подмену цитат, неверные IDs, утечку labels, timeout,
превышение контекста, лимит вывода, digest модели, снимок кода и метрики отказов.

Логи всех 26 запросов повторно проверены: признаков усечения/ненулевых truncated
flags не обнаружено. После старта серии в harness добавлена явная проверка формы
`truncated = N` и автоматическое сохранение source snapshot для следующих запусков;
prompt, sampling и текущие ответы этим не изменены. Точная исполненная версия
сохранена в run; её SHA-256 совпадает с run.json. Это учтённое изменение аудита,
а не незафиксированный перезапуск эксперимента.

С сервера перенесены **115 файлов**, каждый проверен по size/SHA-256.
Archive SHA-256: `43724aac8f67bb79b627ce65c86b36f0005ffa0d6d0dadc2de7828a81c4729b5`.
Все исходные запросы, ответы и логи находятся на обоих hosts. Baseline/source
corpus/holdout не изменены; внешних платных API-вызовов не было. Время — один
измеренный проход, не устойчивый speed benchmark; GPU snapshot не является пиком.

## Что нужно от пользователя

Готовую реализацию искать или устанавливать модели не требуется. Для следующего
исследовательского шага нужна проверка по
[форме без предсказаний](../../data/verification/claim-support-dev-v1/review-worksheet.md):
прочитать claim и его полные sources, отметить supported / contradicted /
insufficient, коротко объяснить решение и указать опорное место. Сомнения можно
оставить unresolved; не нужно угадывать или соглашаться с моделью.

Сначала лучше заполнить форму без чтения подробных verdicts. Это development
calibration; некоторые случаи уже обсуждались в чате, поэтому нельзя называть
всю проверку полностью слепой. После сверки разметки обсудить ошибки наблюдателя
и только затем переходить к одному ограниченному исправлению ответа.
