# Один вопрос в отладчике VS Code

Открыть в VS Code корень `paperqa-reflect`. Профиль **PaperQA: один вопрос пошагово**
использует существующее `.venv`, включает UTF-8, разрешает шаги внутри PaperQA
(`justMyCode: false`) и запускает `smoke-01` на локальных моделях.
Перед запуском задачи автоматически поднимают Ollama и выполняют `doctor`.
Ollama продолжает работать после завершения отладки; журнал и PID находятся в `.cache/ollama`.

## Первая остановка

1. Открыть `.venv/Lib/site-packages/paperqa/agents/main.py`.
2. На строке 312, `action = await agent(agent_state.messages, tools)`, поставить
   точку остановки клавишей F9 или щелчком слева от номера строки.
3. Выбрать профиль **PaperQA: один вопрос пошагово** в Run and Debug и нажать F5.
4. Дождаться жёлтой строки на точке остановки. До неё выполняется подготовка
   документов; это может занять время.

На первой остановке модель ещё не выбрала действие. В Variables раскрыть
`agent_state`, затем `messages`: здесь реальные сообщения, которые получит
управляющая модель. `tools` содержит доступные ей инструменты.
Для первого урока достаточно увидеть вопрос в сообщениях.

## Следующие остановки — по мере разбора

- F10 на строке 312 выполнит выбор действия и остановится после него. Ожидание
  включает реальный вызов локальной модели. Посмотреть `action` и его `tool_calls`:
  имя инструмента и аргументы. Конкретный выбор заранее не гарантируется.
- На строке 317 (`await env.step(action)`) F10 выполнит выбранные инструменты;
  после завершения доступны новые `obs` и обновлённое `env.state`.
- В `tools.py` строка 225: `gather_evidence`. В `state.docs` уже найденные статьи;
  после вызова `aget_evidence` в `state.session.contexts` появятся обработанные фрагменты.
- В `tools.py` строка 323: `gen_answer`. Здесь начинается формирование ответа.
- F5 продолжает до следующей точки; Shift+F5 завершает отладку.

Не нужно ставить все точки сразу. Сначала сообщения → затем выбранное действие
→ затем результат одного инструмента. Исходники установленной библиотеки не редактировать.

## Что отличается от измеренного baseline

`configs/debug-qwen3-8b.json` скопирован из smoke-конфигурации. Изменены название,
метка протокола и тайм-ауты: запрос — до часа, индекс и агент — до четырёх часов,
весь вопрос — до пяти часов. Паузы отладчика учитываются реальным временем,
поэтому лимиты конечны, но позволяют спокойно рассматривать переменные.
Число шагов агента и модели сохранены. Результаты и журналы записываются обычным
способом в новую папку `results/runs`; время такого запуска не использовать
для сравнения производительности. Отладка ещё не означает успешный ответ.

Команда `doctor` проверяет доступность, но не вызывает inference. При выборе
запуска отладки через F5 реальные локальные вызовы моделей начнутся в программе.
