# Сравнение локальных конфигураций PaperQA — протокол v1

Согласовано пользователем 1 октября 2026: «Сравни их, да» после shortlist
Qwen3.5 9B, Ministral 3 8B и Gemma 4 E4B. Nemotron 4B был дополнительным
кандидатом на экономичность; в первую основную тройку не включён.

Это выбор сильного рабочего baseline на ноутбуке, не тест нашего нового механизма.
Данные: неизменные 16 TXT-статей и восемь litqa-dev. Holdout не запускать.
Основной показатель: правильный ответ со штатным завершением (correct_completed).
Дополнительно: raw option match, abstention/failure, подтверждение утверждений
источником, длительность, число инструментов, память и условия исполнения.

## Зафиксированные условия до сравнения

- PaperQA dependency и high_quality prompts/retrieval сохраняются; BGE-M3 dense
  embeddings, chunk 7000/250, evidence_k=20, answer_max_sources=5.
- Контекст 16384, вывод до 4096, seed 42, последовательные запросы, одинаковые
  timeouts 600/1800/2400 s. Индексация отдельно и заново для каждого run.
- Одинаковый JSON-schema-v1 transport; весь выбор инструментов остаётся за моделью.
- Модель каждой основной конфигурации обслуживает controller, RCS и answer.
- Sampling по карточкам/модельным defaults: Qwen general non-thinking .7/.8,
  controller thinking 1/.95, top_k20, min_p0, repeat_penalty1; presence_penalty1.5
  унаследован из закреплённого Ollama model metadata. Gemma 1/.95/top_k64,
  thinking только controller. Ministral .15, без reasoning-override: instruct
  модель не обязана поддерживать thinking. Остальные defaults сохраняются и
  записываются в /api/show. Это сравнение конфигураций, не чистый эффект весов.
- Перед измерением завершить загрузки и синтетические пробы. Между полными
  сериями выгружать модели; не делать одновременные GPU-вызовы. Сохранять
  системные GPU/AC snapshots и /api/ps для memory/offload. Время включает
  неизбежные смены LLM/embedding на одной GPU; это практическая end-to-end задержка.
- Сохранить ошибки и не менять вопросы/ключи по результатам. При несовместимости
  провести ограниченную техническую диагностику и явно отделить исправленную
  конфигурацию от неудачной попытки. Не подсказывать правильные LitQA-ответы модели.

Первый проход — все восемь вопросов у каждого кандидата. Повтор финалистов с
другим seed нужен для оценки устойчивости, если результат допускает выбор по
качеству. Один проход на восьми вопросах не доказывает общую победу; точность и
завершение не заменяют ручную проверку смысла ответов по исходному evidence.
Исторический Qwen temperature=0 сохраняется как отдельная прежняя конфигурация;
его длительность не включать в контролируемое сравнение скорости.

Проверки совместимости в scripts/qualify_model.py — синтетические, не accuracy.
Их source-reading prompt воспроизводит уже известный тип ошибки с ранжированием
чисел и не используется для подбора правильного ответа основной серии.

Источники настроек, проверенные 1 октября:
[Qwen](https://huggingface.co/Qwen/Qwen3.5-9B),
[Ministral](https://huggingface.co/mistralai/Ministral-3-8B-Instruct-2512),
[Gemma](https://huggingface.co/google/gemma-4-E4B-it).

## Адаптация после первой проверки, до завершения основной серии

Qwen с авторскими sampling overrides (`compare-qwen35-dev-s42`) остановлена
оператором после 680 секунд от создания run: первый вопрос не завершён,
повторные gather_evidence не добавляли evidence, gen_answer ещё не вызван.
Это сохранённая незавершённая проверка конфигурации, не результат 0/8 и не
доказательство общей непригодности модели. Причина/время записаны в
`results/runs/20261001T150121Z-5db7fa/operator-abort.json`.

В основную матрицу вместо неё входит повтор ранее квалифицированных настроек
Qwen (`compare-qwen35-stable-dev-s42`, temperature=0). Её результаты измеряются
заново; старые времена не переносятся. Ministral и Gemma сохраняют исходно
выбранные presets. Это адаптивный выбор практических конфигураций на dev, а не
заранее зарегистрированное исследование одинакового бюджета hyperparameter search.
Остановка Qwen — решение помощника по наблюдаемому поведению, не штатное
завершение агента и не заранее предусмотренный общий лимит для всех моделей.

Gemma с controller thinking завершила восемь попыток, но только один цикл
успешно: run `20261001T153658Z-cb9318`. Сохранённый replay без исполнения
инструментов показал два транспортных сбоя: JSON с суффиксом
`<tool_call|><|tool_response>` и пустой content. В обоих сохранённых состояниях
выключение thinking дало валидную команду без изменения схемы или парсера.
Поэтому добавлен отдельный полный run `compare-gemma4-nothink-dev-s42`:
остальные настройки неизменны. Исходный run сохраняется как диагностика
несовместимости, а не доказательство слабого понимания статей. Ollama 0.30.10
сохранена для всех основных измерений; доступность более нового релиза сама
по себе не доказывает устранение конкретного сбоя.

Replay artifacts: `results/diagnostics/20261001T155227Z-controller-replay`,
`20261001T155249Z-controller-replay`, `20261001T155310Z-controller-replay`,
`20261001T155331Z-controller-replay`. Ключи ответов при replay не читаются;
saved state уже содержит предыдущие наблюдения и сгенерированный ответ.

После 7/7 correct_completed у Gemma no-thinking подготовлен повтор seed=43
без иных изменений, после окончания очереди Gemma42/Qwen42. Это заранее
описанная проверка устойчивости перспективного кандидата, а не восемь новых
независимых вопросов. Qwen имеет также исторический прогон того же стабильного
preset на seed42; его времена не подмешиваются в основную таблицу. Фиксированный
seed не гарантирует побитовую воспроизводимость всего агента: остаются случайные
tool-call IDs, различия последовательности запросов и особенности runtime.

Дополнительное решение помощника 16:30 UTC, после более 20 минут повторного
поиска на первом вопросе Qwen stable: дождаться исходного общего timeout агента
(1800 s, плюс fallback под внешним лимитом 2400 s). Если первая траектория
закончится fail/truncated/outer_timeout, остановить оставшуюся серию как провал
повторной проверки устойчивости. Остальные семь вопросов не считать ошибками,
accuracy неполной серии оставить null. Исторический полный Qwen run 7/8
сохранить отдельно; его время не подставлять в контролируемую таблицу.
Это адаптивное ограничение диагностики после наблюдения зацикливания, не
заранее установленное одинаковое правило оценки accuracy для трёх семейств.
